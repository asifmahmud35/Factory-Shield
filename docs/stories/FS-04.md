## Story

As an authenticated Approver, I want to see a queue of incidents awaiting my review, filtered and sorted by priority/SLA, so I can decide which incident to handle first.

## Acceptance Criteria

1. Given I'm authenticated as an Approver, when I `GET /api/v1/approver/queue`, then the API returns only incidents with `status = SUBMITTED` (awaiting triage), not incidents already assigned to others.
2. Given the queue request, then results are sorted by severity (descending: CRITICAL → HIGH → MEDIUM → LOW) and then by created_at (oldest first).
3. Given an Approver who is not in the APPROVER role, then `GET /api/v1/approver/queue` returns HTTP 403 (Forbidden), not 200.
4. Given no incidents in the queue, then the API returns HTTP 200 with an empty array.
5. Given the Angular Approver Queue page, when it loads, then it displays a list of incidents (reference, category, severity badge, created time) in priority order — same status badges as Reporter's "My Incidents" view.
6. Given an incident in the queue, then clicking it navigates to an incident detail view (stub for now, just shows reference + category, no approve/reject buttons yet).

## Dev Notes

**Role-based authorization:** This is the first story where we enforce actual role-based access (Approvers only). The `[Authorize(Policy = "ApproverOnly")]` attribute on the endpoint is the security boundary — the frontend `roleGuard` is UX-only. If an unauthenticated user or Reporter tries to hit this endpoint, backend returns 403.

**Queue sorting:** Severity DESC (critical first) + created_at ASC (oldest first within same severity) — this matches the Approver Epic 2 US-1 requirement for prioritizing review by severity and time.

**Incident detail stub:** Don't build approve/reject/reassign buttons yet — that's FS-05/FS-06. This story is just view-only: show the incident, let the Approver drill into details.
