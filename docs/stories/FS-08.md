# Story FS-08: Save Investigation Details

## Story

As a Resolver working in the Investigation Workspace, I want to fill in investigation details (owner, dates, risk level, notes, findings, immediate actions, lessons learned) and have them auto-saved on blur, so the investigation record is always up to date.

## Acceptance Criteria

1. Given I'm authenticated as Resolver and open the Investigation Workspace, when I call `GET /api/v1/incidents/{id}/investigation`, then the API returns the full `InvestigationWorkspaceDto` including all text fields, checklist items (ordered by `SortOrder`), and timeline events (ordered by `OccurredAt`).
2. Given I update any text field (Notes, Findings, Owner, etc.) and call `PUT /api/v1/incidents/{id}/investigation`, then only the provided non-null fields are updated (patch semantics) and `UpdatedAt` is set to `UtcNow`.
3. Given I provide an invalid `RiskLevel` string, then the field is silently ignored (no crash).
4. Given no investigation exists for the incident, then `GET` and `PUT` return HTTP 404.
5. Given I type in a field and click away (blur), then the Angular workspace shows "Saving…" then "Saved ✓" and the value is reflected on next page load.

## Dev Notes

**Patch semantics:** `SaveInvestigationCommand` checks `if (field is not null)` for each field individually. An empty string clears the value (it's not null). This allows clearing a field by setting it to `""`.

**Risk Level:** Stored as `RiskLevel` enum (High=1, Medium=2, Low=3), transmitted as string. `Enum.TryParse(..., ignoreCase: true)` handles case mismatch.

**Reload after save:** Workspace calls `getInvestigation()` after each successful `PUT` to refresh the signal with the latest persisted values.
