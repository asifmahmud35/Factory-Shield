## Story

As a developer, I want both the .NET backend and Angular frontend scaffolded and connected to PostgreSQL, so that every subsequent story has a working pipe to build on.

## Acceptance Criteria

1. Given the solution is built, when I run `dotnet build`, then `FactoryShield.Domain`, `FactoryShield.Application`, `FactoryShield.Infrastructure`, and `FactoryShield.Api` all compile with no errors.
2. Given the API project runs, when I navigate to `/swagger`, then Swagger UI loads.
3. Given EF Core migrations are applied, then `Users`, `Roles`, and `Incidents` tables exist in PostgreSQL.
4. Given the Angular workspace is scaffolded, when I run `ng serve`, then a blank shell page loads at `localhost:4200`.
5. Given both apps are running, then the Angular app can successfully call a `GET /api/v1/health` endpoint on the .NET API and render the response (proves the pipe end-to-end, not just that both apps boot independently).

- [x] Create .NET solution with 4 projects per architecture.md §8 (Domain, Application, Infrastructure, Api)
- [x] Add EF Core + Npgsql package to Infrastructure, configure `AppDbContext`
- [x] Define `User`, `Role`, `Incident` entities (minimal fields only — full ERD comes later, story by story)

## Dev Notes

Keep entities minimal here — just enough columns to make the migration valid (id, name, etc.). Full field set per the ERD in architecture.md §4 gets added incrementally as each later story needs those specific fields. Don't front-load the whole schema now; that's exactly the kind of scope creep that burns the time budget.
