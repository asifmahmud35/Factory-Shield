## Story

As a Resolver working in the Investigation Workspace, I want to view all evidence attachments for an incident and upload additional files, so the investigation record contains a complete evidence dossier.

## Acceptance Criteria

1. When I open the Investigation Workspace, the Evidence panel loads and displays all existing attachments for the incident (`GET /api/v1/incidents/{id}/attachments`).
2. Each attachment shows: file type icon (or MIME label), evidence note (if present), uploader name, upload date.
3. When I click "Upload Evidence" and select a file, it is uploaded via `POST /api/v1/incidents/{id}/attachments` (multipart form data with optional `evidenceNote`).
4. After a successful upload, the evidence list refreshes automatically.
5. If no attachments exist, the panel shows an empty-state message "No evidence uploaded yet."

## Dev Notes

**Reuse FS-05 upload endpoint:** The existing `POST /api/v1/incidents/{id}/attachments` endpoint from FS-05 handles file upload with optional `evidenceNote`. The Evidence panel in the workspace reuses this endpoint — no new backend work needed for upload itself.

**`GetByIncidentIdAsync`:** Added to `IAttachmentRepository` and `AttachmentRepository`. Uses `.Include(a => a.Uploader)` so `UploaderName` can be mapped from `a.Uploader.Name` (or email fallback).

**File icon:** Frontend maps MIME type prefix to an icon label (`image/*` → 📷, `application/pdf` → 📄, `video/*` → 🎥, default → 📎). No custom icon library needed.

**Empty state:** When `attachments.length === 0`, panel shows grey placeholder text rather than an empty list container.
