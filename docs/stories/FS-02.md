## Story

As an authenticated Reporter, I want to attach a photo or document to an incident I just submitted, so that the Approver and Resolver have visual/written evidence without needing to ask me again.

## Acceptance Criteria

1. Given an authenticated user, when I `POST /api/v1/incidents/{id}/attachments` with a valid file (`multipart/form-data`), then the API stores the file locally, computes a SHA-256 hash, creates an attachment record linked to the incident, and returns HTTP 201 with `attachment_id`.
2. Given the `incident_id` in the URL doesn't exist, then the API returns HTTP 404.
3. Given the uploaded file exceeds 5MB or isn't one of the allowed types (`image/jpeg`, `image/png`, `application/pdf`), then the API returns HTTP 400 with a clear error, and no attachment is created.
4. Given an upload succeeds, then the attachment record has `upload_status = UPLOADED`, `sha256_hash` populated, and `uploaded_by` set to the authenticated user's ID.
5. Given the Angular confirmation screen shown after FS-01's incident creation, then a file input appears, letting the Reporter attach a photo or document to the incident they just created.
6. Given a file is selected and uploaded via Angular, then a success indicator (filename + checkmark) appears on the confirmation screen.

## Dev Notes

This is the first real consumer of `IFileStorageService` (declared but unimplemented until now) — keep the implementation simple: local disk write, return a storage key (relative path is fine for MVP, no need for a CDN-style abstraction yet).

Skip per architecture.md §11 MVP cut: image compression, upload retry-on-failure polish, voice notes, multiple simultaneous file uploads. One file at a time, synchronous upload, is enough to satisfy the story.

Don't build a generic "view attachment" / download endpoint yet — that's only needed once the Approver/Resolver views exist (later stories). For FS-02, uploading and confirming success is the full scope.
