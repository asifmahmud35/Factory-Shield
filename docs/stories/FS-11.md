## Story

As a Resolver, I want to create corrective actions for an incident and track their progress and completion status, so that preventive measures are formally recorded and can be verified.

## Acceptance Criteria

1. When I click "Add Action" in the CAPA Tracker panel, a form appears with fields: Title (required), Priority (Critical/High/Medium/Low), Owner, Due Date, Description.
2. When I submit the form, a new corrective action is created via `POST /api/v1/incidents/{id}/actions` and appears in the list without a page reload.
3. The actions list shows each action's title, priority indicator (coloured dot), status pill, overdue badge (if past due date and not completed/verified), owner, due date, and progress bar.
4. I can drag the progress slider (0–100 %, step 10) to update `completionPercentage` via `PATCH /api/v1/actions/{actionId}`.
5. I can change the status dropdown (Open → InProgress → Completed → Verified) which also calls `PATCH /api/v1/actions/{actionId}`.
6. A `completionPercentage` value is clamped to [0, 100] server-side.

## Dev Notes

**Priority codes:** 1=Critical (red), 2=High (orange), 3=Medium (yellow), 4=Low (green). Sent as integer; frontend maps to CSS class names.

**Status flow** (UI-enforced only, no backend state machine): Open → InProgress → Completed → Verified. Backend accepts any of the 4 strings.

**Overdue badge:** Shown when `dueDate < now` AND `status` is not `Completed` or `Verified`.

**`PATCH` endpoint lives on `ResolverController`** (not `InvestigationController`) to keep action-level operations separate from the investigation workspace endpoints.

**DI registration:** `ICorrectiveActionRepository` → `CorrectiveActionRepository` registered as scoped in `Program.cs`.
