## Story

As a Resolver viewing an assigned incident, I want to open the Investigation Workspace so that I can begin a structured investigation with a pre-seeded checklist and timeline.

## Acceptance Criteria

1. Given I'm authenticated as Resolver, when I call `POST /api/v1/incidents/{id}/investigation`, then the API creates an Investigation record with 8 pre-seeded checklist items and 1 timeline event ("Investigation workspace opened."), and returns `investigationId`.
2. Given the investigation is already open, when I call the same endpoint again, then the same `investigationId` is returned (idempotent).
3. Given a non-existent incident ID, then the API returns HTTP 404.
4. Given a non-Resolver token, then the API returns HTTP 403.
5. Given I click a row in `/resolver/assigned`, then I navigate to `/resolver/incidents/{id}/investigation` and the workspace loads with 8 unchecked checklist items and a "Investigation workspace opened." timeline entry.

## Dev Notes

**Namespace collision:** Application layer uses `FactoryShield.Application.Investigations.Commands` (plural) to avoid collision with `FactoryShield.Domain.Entities.Investigation` type name.

**Idempotency:** Handler calls `FindByIncidentIdAsync` before creating. If investigation already exists, returns its `Id` without creating duplicates.

**Checklist stubs in workspace:** FS-07 renders the 8 items from hardcoded labels (matching the seeded DB data). FS-09 will load them from `GET /incidents/{id}/investigation` and wire toggle calls.
