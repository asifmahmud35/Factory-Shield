## Story

As an authenticated Reporter, I want to see a list of incidents I've submitted along with a simple status, so I know what's happening with my reports without needing to ask anyone.

## Acceptance Criteria

1. Given I'm authenticated, when I `GET /api/v1/incidents/mine`, then I receive only incidents where `reporter_id` matches my user ID (from the JWT claim, not a request parameter).
2. Given an incident has a canonical `status`, then the response includes a computed `display_status` (mapped per Dev Notes), not the raw internal status string.
3. Given I have no submitted incidents, then I get HTTP 200 with an empty array, not an error.
4. Given the Angular "My Incidents" list page, then it shows each incident's `incident_reference`, `category`, `severity`, and `display_status` as a visual badge.
5. Given I'm not authenticated, then `GET /api/v1/incidents/mine` returns HTTP 401.
6. Given the list page, then a button/link exists to navigate to the report form (FS-01) to submit a new incident.

## Dev Notes

**Display status mapping (MVP-scoped):** Since FS-01 deliberately built only the simplified MVP status enum (`SUBMITTED, TRIAGED, ASSIGNED, IN_PROGRESS, RESOLVED, CLOSED, REJECTED` — not the full 16-state Governance machine), the `display_status` mapping here is the MVP-scoped subset of the full table in architecture.md §3.2:

| Canonical status | display_status |
|---|---|
| SUBMITTED, TRIAGED | Submitted |
| ASSIGNED, IN_PROGRESS | In Progress |
| RESOLVED, CLOSED | Resolved |
| REJECTED | Rejected |

Don't try to map states that don't exist yet in this MVP (INVESTIGATION, RCA_REVIEW, etc.) — that mapping only matters if the full governance pipeline gets built post-submission.

**StatusBadgeComponent:** This is the first real use of the shared `status-badge` component architecture.md §9 lists. Build it as a small, reusable, input-driven component now (`@Input() status: string`) — Approver and Resolver views in later stories will reuse it for their own status displays, so keep it generic rather than Reporter-specific.
